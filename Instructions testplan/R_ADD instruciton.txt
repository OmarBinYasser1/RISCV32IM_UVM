3. Overflow / wraparound
0xFFFFFFFF + 1  = 0x00000000
0x80000000 + 0xFFFFFFFF = 0x7FFFFFFF

4. Register corner cases
you need to test the register fields.
x0
x1
x15
x30
x31
ADD x0, x1, x2 --> x0 = 0
5. Same-register cases
These are useful corner cases:
ADD x1, x1, x2
Expected 
x1 = old_x1 + old_x2.

ADD x1, x2, x1
ADD x1, x1, x1
x1 = 2 × x1
These are excellent for detecting register read/write problems.
6. Encoding verification
For ADD, verify the decoder recognizes the correct:
opcode
funct3
funct7
You don't necessarily need a separate test for every possible register encoding if your constrained-random test varies rd, rs1, and rs2.

But you should have coverage for those fields.
7. PC behavior
PC_next = PC + 4

8. Back-to-back dependency (Pipelined)

This is especially important if your core is pipelined.

Example:
ADD x5, x1, x2
ADD x6, x5, x3
Expected
x5 = x1 + x2
x6 = x5 + x3
Also test 
ADD x5, x1, x2
ADD x5, x5, x3
These can expose forwarding/stalling/register-file timing bugs.
